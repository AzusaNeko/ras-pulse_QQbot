## 背景

`MonitorEngine` 当前通过 `newItem` 和 `favoriteUpdate` 事件暴露已经完成基线、过滤、去重和更新识别的商品变化。Electron 主进程订阅这些事件：`newItem` 会广播给渲染进程，在全局及关键词级 Windows 弹窗均开启时触发桌面通知，并触发 QQ 推送；`favoriteUpdate` 会广播给渲染进程并触发桌面通知。

应用设置保存在 `state.json`，旧状态通过默认值合并和规范化加载保持兼容。QQ `AppSecret` 不进入应用设置，而是由主进程通过 Electron `safeStorage` 加密后另行保存，渲染进程只获得 `secretConfigured`。Bark 设备密钥应复用这一安全模型。

## 目标与非目标

**目标：**

- 用户离开电脑后，仍能在多台 iPhone 上收到商品上新、旧商品更新和收藏变化。
- Bark 与桌面通知、QQ 推送独立启停，任一通道失败不得影响监控轮询和其他通知通道。
- 支持官方 Bark Server 及一个自建 Server，兼容局域网 HTTP 部署并明确提示风险。
- 已保存的 `deviceKey` 不进入普通设置，不从主进程回传渲染进程，也不进入日志或错误文本；用户在密码输入框中本次录入的值只用于提交保存。
- 通过有限重试降低短暂网络故障造成的漏推，同时限制重复通知。
- 保持现有状态文件兼容，旧用户升级后 Bark 默认关闭。

**非目标：**

- 首版不抽取通用 TypeScript `NotificationProvider` 多厂商框架，也不实现 Pushover、ntfy 等其他适配器。
- 不提供 Bark 设备级关键词、事件或通知等级过滤。
- 不支持多台设备分别连接不同 Bark Server。
- 不支持 `critical`、`call`、自定义 `sound` 或 Bark `ciphertext` 内容加密。
- 不建立持久化补发队列，不在应用重启后补发失败消息。
- 不改变桌面通知图片、名称、价格和声音设置，也不改变 QQ 推送范围。

## 技术决策

### 1. 在主进程通知分发处建立 Bark seam

新增独立的 `BarkNotifier` 模块，由主进程在 `newItem` 和 `favoriteUpdate` 事件处理器中调用。监控引擎仍只识别业务事件，不感知 Bark、APNs、设备密钥或重试规则。

`BarkNotifier` 对调用方隐藏消息格式、Bark 请求、密钥读取、逐设备并发、超时、重试和日志脱敏。首版只有一个手机推送实现，因此不提前增加通用多厂商接口；未来出现第二个真实适配器时，再从已经稳定的调用方式提取公共接口。

### 2. 配置元数据与设备密钥分离

普通应用设置保存以下非秘密元数据：

- 全局启用状态，默认关闭。
- 全局 Bark Server，默认 `https://api.day.app`。
- 全局通知等级，默认 `active`，可选 `timeSensitive`。
- 是否携带商品图片，默认开启。
- Bark 设备列表；每项包含稳定 ID、显示名称和启用状态。

每台设备的 `deviceKey` 以稳定设备 ID 为索引，通过 Electron `safeStorage`/Windows DPAPI 加密后保存在独立密钥文件。读取配置时，主进程只向渲染进程返回 `keyConfigured`，不得返回明文或密文。保存时空白密钥表示保留已有值；删除设备时同步删除对应密钥。

旧状态缺少 Bark 字段时使用上述默认值，不进行破坏性迁移，也不自动开启手机推送。

### 3. 使用专用 Bark 配置 IPC

Bark 配置不通过通用 `settings:update` 直接写入，因为保存设备列表时还要同步校验和更新独立密钥。新增专用的配置读取、配置保存、设备删除及设备测试 IPC，并通过预加载桥接暴露最小能力。

保存前执行已确认的最小规则：Server 必须是完整的 HTTP/HTTPS 地址；设备 Key 不得为空；同一 Server 下不得出现重复 Key；空设备名称自动生成顺序名称；不猜测 Key 的长度和字符格式。

启用全局 Bark 时，必须至少存在一个已启用且已配置 Key 的设备。单个设备可以在全局关闭时测试，也可以在自身停用时测试，以便先验证配置再正式启用。

### 4. 逐设备使用 Bark V2 JSON 请求

每台启用设备独立向当前 Server 的 `/push` 端点发送 JSON POST，将 `device_key` 放在请求体中而不是 URL 中，降低代理、访问日志和错误文本意外记录 Key 的概率。网络调用使用 Electron `net.fetch`，以沿用 Chromium 系统代理、PAC、HTTPS 隧道和代理认证行为。

不使用 `device_keys` 批量请求。逐设备请求可以准确隔离无效 Key、网络失败和测试结果，保证单台失败不阻止其他设备。

Server 地址允许 `http://` 和 `https://`。设置页对 HTTP 显示持续可见的明文传输警告，但不阻止保存、测试或发送。地址拼接必须保留用户配置的反向代理路径，并规范处理末尾斜杠。

### 5. 固定通知内容与分组

商品上新通知使用“发现上新 · 关键词”标题；旧商品更新使用“旧商品更新 · 关键词”；收藏变化使用“收藏商品状态变化”。正文始终包含商品名称、当前价格，并在存在变化时包含更新摘要、原价或售出状态。通知点击后打开经过现有 Mercari URL 规则构造的商品链接。

关键词商品按关键词设置 Bark `group`，收藏变化使用固定收藏分组。全局等级映射为 `active` 或 `timeSensitive`。图片开关开启且缩略图 URL 受现有 Mercari 图片域名规则支持时，使用 Bark `image` 字段发送缩略图媒体附件；图片缺失或不受支持时省略 `image`，不得阻止文字通知。`icon` 只用于替换 Bark 通知图标，不能满足商品图片展示需求，因此不得用它代替 `image`。

请求不指定 `sound`、`critical`、`call` 或 `ciphertext`。手机是否响铃及使用何种声音由各设备的 Bark App 和 iOS 设置决定。

### 6. 有限重试与失败隔离

每次请求设置有界超时。网络错误、超时或 HTTP 5xx 在两秒后重试一次；HTTP 4xx 直接判定该设备发送失败；其他非成功响应不得无限重试。重试只保存在当前进程内，应用退出后丢弃。

逐设备结果通过 `Promise.allSettled` 或等价方式汇总。正式通知失败只写入应用诊断日志和控制台，不回滚商品动态、不阻塞事件处理器，也不影响桌面通知、QQ 推送或其他 Bark 设备。诊断内容只包含设备显示名称、稳定 ID、错误类别和脱敏 Server，不得包含 Key、完整请求体或含 Key 的 URL。

一次请求可能已经被 Server 接收但响应丢失，因此单次重试可能产生重复通知。当前需求优先降低高时效商品漏推概率，接受这一有限重复风险。

### 7. 设置界面与测试流程

在偏好设置中新增独立 Bark 手机推送区域，展示全局开关、Server 地址、通知等级、图片开关和设备列表。设备支持添加、命名、启停、更新 Key、删除及单独测试；已经保存的 Key 只显示“已保存”，不会回填到输入框。

测试使用与正式发送相同的网络、超时、重试、消息构造和脱敏路径。存在最近商品时，以该商品生成带“测试”标识的预览通知；没有商品时发送不含商品链接和图片的通用测试内容。测试结果明确指出目标设备成功或失败，不能只以 HTTP 请求已发起作为成功。

### 8. 测试 seam 与验证边界

`BarkNotifier` 接收可注入的请求函数、等待函数和密钥读取依赖，使测试可以验证请求体、超时分类、两秒重试、4xx 不重试和多设备失败隔离，无需访问真实 Bark Server。

配置规范化、IPC 输入校验、密钥不回传、设备删除清密钥及设置界面交互分别覆盖。OpenSpec 严格校验、单元测试、类型检查和生产构建只能证明文档与本地实现质量；真实 iPhone、APNs、专注模式、自建 Server 和系统代理仍需单独验收。

## 风险与权衡

- **风险：HTTP 自建 Server 泄露 Key 和通知正文。** → 允许用户选择以保留局域网部署能力，同时在设置页持续警告；默认仍为 HTTPS。
- **风险：公共 Server 或 APNs 可见通知正文。** → 首版不实现内容加密；对隐私要求更高时使用自建 Server，后续可在不改变业务调用方的情况下增加加密。
- **风险：同一事件对多设备发送造成瞬时并发。** → 设备规模是个人使用量级，逐设备并发换取明确的部分失败语义；不做无限并发队列。
- **风险：Key 轮换或设备迁移后失效。** → 设备测试和按设备更新 Key 提供恢复路径；4xx 不进行无意义重试。
- **风险：缩略图失效或 Bark 无法加载。** → 图片仅为可选 `image` 媒体附件，正文和链接独立发送。
- **风险：旧状态缺失新增字段。** → 使用默认值规范化加载，Bark 保持关闭且设备列表为空。

## 迁移与回滚

升级时不改写已有订阅、商品动态、收藏或 QQ 配置。旧 `state.json` 在加载时补齐 Bark 默认元数据；首次保存后按现有原子写入方式持久化。设备 Key 只在用户保存 Bark 设备后写入独立加密存储。

回滚代码时，旧版本会忽略新增 Bark 设置字段；独立密钥文件可保留供再次升级使用。若用户在新版本删除 Bark 设备，对应密钥应已经删除，回滚不会恢复。
