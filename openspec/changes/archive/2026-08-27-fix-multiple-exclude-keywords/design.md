## 背景

`Subscription.excludeKeyword` 以字符串保存。桌面界面允许用户用中文逗号、英文逗号、顿号或换行输入多个排除词，并将多个词规范化为顿号分隔的展示字符串。`MercariClient` 当前把该字符串直接写入 `searchCondition.excludeKeyword`。

真实接口对照表明：单个排除词可以生效；顿号或逗号分隔的多个排除词会被当成一个完整短语；空格分隔时，Mercari 能分别排除所有词项。因此问题同时涉及外部接口适配和本地容错。

## 目标与非目标

**目标：**

- 多个排除词在 Mercari 请求中全部生效。
- 即使 Mercari 返回命中排除词的商品，应用也不得把它加入商品动态或发送提醒。
- 用户给已有关键词追加排除词后，已有商品动态中的命中项立即消失。
- 兼容现有顿号、逗号和换行分隔的持久化数据。

**非目标：**

- 不改变 QQ 目标级屏蔽词的数据模型和推送语义。
- 不在本次改造中提供删除单个排除词的界面。
- 不修改 Mercari 搜索排序、基线或已见商品集合的语义。

## 技术决策

### 1. 统一解析排除词

新增共享工具，将中文逗号、英文逗号、顿号和换行识别为词项分隔符，去除空白项并按大小写不敏感方式去重。界面和持久化仍可使用顿号展示，避免数据迁移。

备选方案是在 `MercariClient` 内临时替换顿号。该方案无法覆盖逗号、换行、重复词和本地过滤，因此不采用。

### 2. 请求层使用空格拼接

`MercariClient` 必须把解析后的词项用单个空格拼接后写入 `searchCondition.excludeKeyword`。该格式已经由真实 Mercari API 对照验证。

### 3. 监控引擎执行本地兜底

`MonitorEngine` 在处理 `ItemSource.search` 返回值前，按商品标题执行规范化后的包含匹配。过滤发生在基线、上新和旧商品更新判断之前，因此命中项不会进入已见判断、动态记录或通知流程。

把兜底放在监控引擎而不是只放在 `MercariClient`，可以覆盖测试源以及未来其他 `ItemSource` 实现，并能使用请求期间刚刚更新的排除词。

### 4. 更新排除词时清理现有动态

当 `MonitorEngine.update` 收到 `excludeKeyword` 变更时，立即过滤该订阅已有的 `recentItems`。收藏记录不属于关键词搜索动态，不随排除词清理。

## 风险与权衡

- **风险：商品标题存在全角、半角或大小写差异。** → 匹配前执行 Unicode `NFKC` 规范化和小写转换。
- **风险：排除词包含空格且用户希望按完整短语匹配。** → 本地解析只把逗号、顿号和换行视为多个词的分隔符；词项内部空格保留。Mercari 请求中的空格属于外部接口协议，本地匹配仍按完整词项执行。
- **风险：更新排除词时正有搜索请求执行。** → 监控引擎在请求返回后使用当前订阅值再次过滤，避免竞态请求写入过期结果。

## 迁移与回滚

无需迁移现有状态文件。发布后首次更新或检查会使用新解析规则；更新排除词时会清理当前动态中的命中项。回滚只需恢复代码，持久化格式保持兼容。
